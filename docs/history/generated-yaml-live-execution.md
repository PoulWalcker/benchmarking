## Question and claim

Can unchanged model-authored `sapi-lab/v0` YAML pass independent business and
native n8n checks when its LLM operations use the existing live wrapper?

The hypothesis is that one frozen submission per existing family will retain
its accepted behavior when only runtime LLM mode changes. The first experiment
is **frozen replay**: historical model-generated bytes, current compiler and
verifier, fresh n8n executions, and fresh runtime model responses. It does not
test fresh generation, held-out generalization, another executor, refinement,
lifecycle, or full natural-language correctness.

## Evidence that a model was reached

Keep three counts distinct:

1. **Agency HTTP attempts:** native n8n HTTP-node executions, including failures.
2. **Upstream wrapper attempts/completions:** records at the adapter's actual
   outgoing `urlopen` call and returned wrapper result. Validate `ok: true`,
   `exit_code: 0`, bounded output, strict JSON/schema, and restricted model
   identifier; retain hashes and available CLI token telemetry without treating
   it as a complete token/cost breakdown.
3. **Provider-internal requests:** provider receipts or existing downstream
   telemetry, if available, may establish these separately. Model names or
   HTTP 200 responses alone do not establish provider-internal request counts.

The sufficient evidence for this scoped live experiment is a confirmed dispatch
to the real existing codex-exec wrapper plus its successful model completion,
correlated with native n8n execution. Inspect the unchanged wrapper's dispatch
implementation/configuration read-only and record its private identity; ensure
the endpoint actually routes to codex-exec and has no configured stub or response
substitution. Capture the allowed successful wrapper response metadata at the
outgoing seam, including model identity, completion status, hashes, and available
CLI token telemetry. Record any observed lower-layer retries. The wrapper is a
trusted part of this research setup, not an independently attested provider.

The historical live report has eight distinct invocation IDs, all correlated
with the workflow traces, and eight completed HTTP-200 bridge audit rows carrying
the model `gpt-6-astra`. Its rows have input hashes, durations and timestamps;
they have no provider request receipts or separate upstream dispatch events.
The new outgoing audit strengthens this evidence without changing the wrapper.

Keep `provider_call_count: null` when provider receipts are unavailable, even
when the scoped live experiment passes. Report “eight confirmed wrapper/model
completions” only with the dispatch/response chain above; never relabel that as
eight proven paid provider requests. Missing provider-internal telemetry is a
documented limitation, not a new blocker. An unavailable real wrapper or absent
dispatch/completion evidence is a failed preflight or inconclusive execution.
Use existing stronger evidence when available; redact paths, credentials,
session contents, and raw stderr and retain only allowlisted fields.

Reconcile each run with a single private table joining scenario/case, submission
hash, workflow/execution IDs, logical step, native HTTP node, invocation ID,
operation, input/prompt hashes, adapter dispatch/completion, and wrapper response
evidence; attach provider receipts separately when available. Require a one-to-one
match, including zero unmatched/duplicate calls.
Input hashing must use one documented canonical JSON encoding. The native HTTP
response, Restore event, and audit must agree; a workflow-authored trace alone
cannot supply native proof. Retain runtime provider counts as unknown unless
provider receipts or equivalent provider-level evidence are attached explicitly.

## Controls, budget, and stopping

Run all unpaid gates on the final frozen sources first:

- Existing local checks and distribution privacy checks; fresh `./run.sh`
  oracle/nop controls and all 12 real-n8n fake-bridge probes. The expected current
  control baseline is 35 n8n executions and nine compile rejections.
- Full stub verification of the three selected generated submissions: 32 cases,
  comprising 23 n8n executions and nine expected compile rejections. Preserve
  native wrong-result executions and verifier-only corruption checks. A failed
  generated replay is a failed gate, never a reason to replace its submission.
- Focused local negative controls for hash/source mismatch, missing native
  Agency evidence, duplicate/unmatched invocation, forged audit completion,
  wrapper failure, malformed output, outgoing budget overflow, and timeout.
  Fakes must never contact the real wrapper.

The paid phase has three scenario trials, seven fresh n8n cases, **zero new YAML
generation calls**, and a maximum of **eight outgoing runtime wrapper attempts**,
with operation limits of two per LLM operation in the table. Unexpected
operations, duplicate invocation IDs, a ninth attempt, or excess per-operation
count are rejected before dispatch. Serial execution and a shared run-local
failure latch prevent subsequent model requests after the first observed
failure. Stop scheduling remaining trials when that latch trips; preserve them
as not run. Existing source and container preservation requirements still apply.

This adapter budget is not a proven paid-provider-request cap if the wrapper or
CLI retries internally. Inspect that behavior during preflight and report known
lower-layer retries or unknown retry behavior separately. There is no reliable
currency-cost field; do not invent a dollar estimate or use incomplete token
counts as cost.

Retain current bounded timeouts: 185 seconds adapter→wrapper, 190 seconds for
the n8n HTTP node, 600 seconds workflow deadline, 690 seconds n8n process ceiling
for a live case, 180 seconds import, 1800 seconds Harbor verifier, and 2400 seconds
for the live Harbor job. Keep Harbor `--max-retries 0`, one attempt, no transport
retry, no YAML repair, no prompt adjustment, and no fallback to stubs. Validate
these settings in staged artifacts before dispatch. A timeout may leave an
upstream request running because cancellation is not propagated; mark its model
outcome unknown, disarm further dispatches, and inspect existing wrapper activity
read-only before any later series. Never retry that request silently.

Classify failures independently as provenance/preflight, YAML/profile,
compilation, Harbor/environment, n8n import, n8n execution, Agency transport,
upstream wrapper failure, model output contract, business acceptance, evidence
correlation, budget, or timeout/unknown outcome. Keep stage and raw private
artifacts even if a later layer also fails. Do not replace a business rejection
with an infrastructure success or rewrite a failed report.

Overall success requires all gates, seven independent acceptances, three Harbor
rewards of 1, exactly the expected eight reconciled live completions with the
required model evidence, zero invoice calls, unchanged source/artifact hashes,
and preservation of existing containers/workflows/wrapper. Missing wrapper
dispatch/completion proof is inconclusive for the live-flow claim; an observed
incorrect result is a failed hypothesis for this fixed sample. Any mismatch or budget violation
stops the series. A later diagnostic or repeated run gets a new directory and
keeps the failure in the evidence set.

## Commands and private artifacts

```bash
uv sync --locked --extra harbor

uv run --locked ruff format --check src tests verification infra

```

`./run.sh --live` and `sapi-lab live --stub-report PATH` currently execute
hand-authored reference YAML. `./run-generation.sh --attempts 1` currently makes
three fresh generation calls and executes their workflows with stubs. Setting
an environment variable around it is not a supported combined-run interface.
`sapi-lab execute --llm-mode live --bridge-url URL` can execute arbitrary YAML
where n8n is installed, but supplies neither Harbor orchestration nor independent
acceptance and is not the experiment described here.

The following interface is **implemented**. The explicit live command also requires
`--wrapper-evidence` from the read-only inspection described in the [usage guide](../GENERATED-LIVE.md). Replace
placeholder paths with new, concrete paths. The optional standalone unpaid form is:

```text
uv run --locked --extra harbor sapi-lab live \
  --stub-report reports/<fresh-control-run>/report.json \
  --submissions-manifest reports/<selection-run>/selection.json \
  --report-dir reports/<new-generated-live-preflight> --preflight-only
```

An invocation with a new report directory, without `--preflight-only` and with
`--wrapper-evidence` runs the full unpaid gates before the bounded live phase.
A separate preflight invocation is optional. The command shows selected artifact
hashes, the call ceiling and evidence prerequisites before dispatch. A fresh
independent execution remains necessary to establish the live claim.

Use only new private `reports/<UTC>-generated-live/` directories:

```text

jobs/live-<scenario>/           # serial Harbor trial/native case artifacts

```

Reference the separate fresh control report by path and hash. Record these
fields in the versioned experiment report schema, without rewriting the
historical report schema. Git, Docker context, wheels, and source archives must
continue to exclude this entire output tree. Public summaries contain only
curated counts, hashes, limitations, and relative evidence identifiers; never
host-specific paths, wrapper secrets, raw prompts/responses, or environment dumps.

## Follow-on distinction and dependency

Fresh generation is a later, separately identified series. Use current English
prompt inputs, one generation attempt per scenario, and save their new hashes.
Freeze every unedited answer before stub/live evaluation. A malformed or rejected
answer remains a failure; no replacement with historical YAML or repair. The
comparable pilot would add three generation requests to the eight runtime
requests, with independent phase budgets. `generation/run.py` and
`generation/agent.py` currently label runtime as stub; changing that lifecycle
requires explicit implementation and tests. This replay task does not promise
that command or a fresh-generation success rate.

The implementation adds manifest ingress, unpaid preflight, audit/budget controls
and evidence reconciliation to the existing live experiment module. Its fresh
local, real-n8n and live gates determine acceptance.
No further task-family decision is needed. The external dependency is a working,
unchanged real codex-exec wrapper whose dispatch behavior is checked read-only;
provider-internal telemetry remains optional and its absence is reported. Subsequent
[scenario expansion](scenario-expansion.md) should consume this baseline rather
than combining new task semantics with the first generated/live trial. A future
commit, if requested, must use Conventional Commits; this preparation creates no
commit, remote, or push.

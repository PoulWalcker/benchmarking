# Domain docs

This repository uses a single-context layout.

Before exploring domain concepts or decisions, read the root
`GLOSSARY.md` and relevant ADRs under `docs/adr/`, when present.
If absent, proceed silently. The domain-modeling skill creates
them when terms or decisions are resolved.

Use glossary terms consistently in issues, proposals, hypotheses
and tests. When a needed term is missing, reconsider the wording
or note a vocabulary gap for domain-modeling.

Explicitly identify any proposal that conflicts with an existing
ADR and explain why the decision should be reconsidered.

Keep current architecture and ownership in `docs/ARCHITECTURE.md`;
glossary entries define terms and ADRs record decisions without
duplicating that document.
